# Обоснование декомпозиции

Я разбил код так, чтобы каждый файл делал одну понятную вещь. `App.vue` только собирает экран: показывает лоадер, ошибку или список. Как выглядит карточка и поле поиска ему все равно. Запрос к API и флаги loading/error лежат в `useUsers`, поиск по уже загруженным юзерам в `useSearch`. `UserFilters` отвечает за ввод, `UserList` и `UserCard` за список, `ErrorMessage` и `EmptyState` за свои сообщения. Так проще читать код и не смешивать верстку с запросами.

Store не использовал. Экран один, данные никуда больше не уходят. Список берется в `useUsers` и передается в `useSearch`, по моему мнению, этого хватает. Pinia здесь была бы лишней оберткой.

Debounce, throttle и `AbortController` тоже не добавлял. Mock один раз отдает 25 юзеров, дальше поиск идет по массиву в памяти. Задерживать ввод нет смысла: на бэкенд мы больше не ходим. `AbortController` нужен, когда запросы можно слать подряд и старый ответ может прийти позже нового. Повторы, пагинация и кэш аналогично, это для живого API, а не для этого задания.
